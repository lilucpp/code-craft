# Unix 经典接口设计模式全集 (Interface Design Patterns)

> 整理自埃里克·雷蒙德（Eric S. Raymond）《UNIX编程艺术》第11章。

---

## 一、 10 大经典接口模式及工程选型

### 1. 过滤器模式 (Filter Pattern)
* **特征**：无交互，从 `stdin` 读取数据流，进行转换/过滤后写入 `stdout`。
* **经典实例**：`grep`, `sed`, `awk`, `tr`, `sort`, `jq`。
* **工程准则**：
  * **管道友善**：绝不污染 `stdout`（不打印日志或修饰文字）；
  * **容错性**：遇到无法解析的脏行时，将警告输出至 `stderr`，不要直接中断管道。

### 2. Cantrip 模式
* **特征**：最简单的设计模式。无输入、无数据输出，一次调用只干一件事，仅产生退出状态码（Exit Code）。
* **经典实例**：`touch`, `rm`, `clear`, `mkdir`。
* **工程准则**：
  * 状态码约定：`0` 代表完全成功，`非 0`（如 1~255）代表特定错误类型；
  * 天生具备最强的自动化与脚本调用能力；如果一个操作不需要用户交互，**默认优先设计为 Cantrip 模式**。

### 3. 源模式 (Source Pattern)
* **特征**：无输入或仅接收命令行配置参数，自主生成数据流并输出到 `stdout`。
* **经典实例**：`ls`, `find`, `ps`, `cat`。
* **工程准则**：输出应格式化为规整的行或分隔文本（DSV/JSON Lines），便于下游过滤器消费。

### 4. 接收器模式 (Sink Pattern)
* **特征**：纯消费型。从 `stdin` 接收数据流，送往特定硬件设备、存储或远程日志收集系统。
* **经典实例**：`lpr`（打印机调度）、`logger`（系统日志转储）、`/dev/null`。

### 5. 编译器模式 (Compiler Pattern)
* **特征**：批量输入一个或多个规格源文件，经过编译/翻译后生成对应的二进制或目标代码文件。
* **经典实例**：`gcc`, `javac`, `tsc`, `protobuf-compiler`。
* **工程准则**：操作过程保持安静；若有语法/编译错误，格式化输出包含 `文件名:行号:列号: 错误描述` 的定位信息。

### 6. ed 模式 (ed-like Batch Editor)
* **特征**：通过输入预设的简短编辑指令集来修改文件内容，适合在自动化脚本中做精准的文本替换。
* **现代变种**：Ansible 的 `lineinfile`，各类自动化补丁打桩工具。

### 7. Roguelike 模式 (全屏终端 TUI)
* **特征**：全屏字符阵列界面，单键触发操作，无需频繁刷新整个屏幕。
* **经典实例**：`top`, `htop`, `vim`, `ncdu`, `lazygit`。
* **工程准则**：用于提供比传统 CLI 更直观的可视化交互，同时避免引入重量级图形桌面依赖。

### 8. 引擎与接口分离模式 (Separation of Engine and Interface)
* **特征**：**最核心、最推荐的现代系统架构模式**。
  * **引擎层 (Engine)**：作为无状态的计算核心、业务模型与数据处理器（通常是独立的 CLI 或 Daemon 进程）；
  * **接口层 (Interface)**：作为轻量级的前端展示（GUI、Web 前端、移动端或高级 CLI 包装器）。
* **通信机制**：通过 IPC、Unix Domain Socket、标准输入输出管道或 REST/gRPC 传输纯文本协议。
* **架构优势**：
  * 前端崩溃或改版不会影响计算引擎的运行；
  * 极易编写自动化测试用例针对引擎进行无头（Headless）测试。

### 9. CLI 服务器模式 (CLI Server)
* **特征**：后台常驻守护进程，监听标准输入或本地 Socket，接收类 CLI 的简短文本命令（如 `GET`, `SET`, `STATUS`）并返回响应。
* **经典实例**：Redis, Memcached, 早期的 SMTP/POP3 守护程序。
* **工程优势**：排错极其透明，开发者仅凭 `nc` (netcat) 或 `telnet` 即可直接手动键入命令进行调试。

### 10. 基于微型语言的接口模式 (Minilanguage / DSL)
* **特征**：为特定领域的复杂业务定义一套轻量声明式语言。
* **经典实例**：`cron` 表达式、正则表达式、SQL、PromQL。
* **工程准则**：当使用传统参数配置组合已经极其繁复混乱时，引入声明式微型语言能够大幅提升表现力。
