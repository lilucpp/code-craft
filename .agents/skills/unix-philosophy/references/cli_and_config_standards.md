# 命令行设计与配置分层工程规范 (CLI & Config Standards)

> 整理自埃里克·雷蒙德（Eric S. Raymond）《UNIX编程艺术》第10章。

---

## 一、 5 级配置覆盖优先级模型

开发任何具备配置能力的命令行工具、后台守护进程或微服务时，必须严格执行以下自底向上的覆盖法则（高优先级无条件覆盖低优先级）：

```
[优先级 1 (最低)] 代码内置硬编码默认值 (Compiled-in Defaults)
      ↓
[优先级 2] 系统级全局配置文件 (/etc/app/config.conf 或 /etc/app.d/)
      ↓
[优先级 3] 用户级目录配置文件 (~/.config/app/config 或 ~/.apprc)
      ↓
[优先级 4] 环境变量 (APP_CONFIG, APP_TIMEOUT, APP_LOG_LEVEL)
      ↓
[优先级 5 (最高)] 命令行显式参数 (--timeout 30, -v, -c /path/to/custom.conf)
```

### 最佳工程实践：
1. **不要在全局硬编码任何动态变量**：路径、超时时间、端口号必须提供默认值，但允许各层覆盖。
2. **环境变量命名空间隔离**：必须带有清晰的前缀（如 `APP_`、`TOOL_`），防止与宿主操作系统的标准环境变量冲突。
3. **配置热加载或显式查看**：提供 `--dump-config` 或 `--dry-run` 参数，方便输出最终生效的配置解析全景树。

## 二、 命令行单字符选项标准语义字典 (`-a` ~ `-z`)

遵循 POSIX / GNU 业界共识，严禁标新立异：

| 选项 | 标准语义 (POSIX/GNU Convention) | 说明与典范 |
| :--- | :--- | :--- |
| **`-a`** | **All / Append** | 处理所有项目（如 `ls -a`），或追加内容（如 `tar -a`）。 |
| **`-b`** | **Batch / Block size** | 批处理非交互模式（禁用确认提示），或设置缓冲块大小。 |
| **`-c`** | **Command / Config** | 紧跟要执行的脚本/命令（如 `bash -c`），或指定配置文件路径。 |
| **`-d`** | **Debug / Directory** | 开启 Debug 调试日志输出，或指定运行的工作目录。 |
| **`-e`** | **Execute / Expression** | 执行单行表达式（如 `sed -e`, `perl -e`）。 |
| **`-f`** | **Force / File** | 强制执行不提示（如 `rm -f`），或指定输入文件路径。 |
| **`-h`** | **Help / Human-readable** | 打印简要使用帮助，或以易读格式输出（如 `df -h`）。 |
| **`-i`** | **Interactive** | 破坏性操作前强制弹出确认提示（如 `rm -i`）。 |
| **`-k`** | **Kill / Keep** | 终止正在运行的进程，或保留临时中间文件。 |
| **`-l`** | **List / Long format** | 列出资源，或使用长格式详细列表（如 `ls -l`）。 |
| **`-m`** | **Message / Mode** | 附加提交说明（如 `git commit -m`），或设置文件权限模式。 |
| **`-n`** | **Dry-run / Number** | 仅模拟试跑不产生实质改动（如 `make -n`），或为行输出编号。 |
| **`-o`** | **Output** | 指定最终输出的目标文件或目录（如 `gcc -o`）。 |
| **`-p`** | **Port / Path** | 指定网络监听端口，或指定查找路径。 |
| **`-q`** | **Quiet / Silent** | 静默模式，压制一切普通提示信息，仅在出错时报出异常。 |
| **`-r`** / **`-R`** | **Recursive** | 递归向下遍历子目录（如 `cp -r`）。 |
| **`-s`** | **Silent / Size** | 静默运行（同 `-q`），或指定大小限制。 |
| **`-u`** | **User / Update** | 指定目标运行用户，或仅在源文件更新时执行同步。 |
| **`-v`** | **Verbose / Version** | 详细打印运行过程；大写 **`-V`** 通常专门用于输出版本号。 |
| **`-w`** | **Wait / Watch / Width** | 设置等待超时时间，开启文件监听，或指定终端输出宽度。 |
| **`-x`** | **Extract / Execute** | 解压归档包（如 `tar -x`），或开启脚本追踪执行（如 `sh -x`）。 |
| **`-y`** | **Yes** | 自动对所有交互式询问回答 Yes。 |

## 三、 命令行高级通用准则

1. **单连字符与双连字符互补**：
   - 常用高频选项使用单字符短选项（`-f`）；
   - 语义复杂的选项必须提供双连字符长选项（`--force`），便于编写可读性强的维护脚本。
2. **`--`（双横线单独使用）必须受支持**：
   - 标志着命令行选项解析的绝对终结；
   - 之后的任何参数，哪怕以 `-` 开头（例如处理名为 `-test.txt` 的特殊文件），都必须被严格作为普通字面值文件名/参数处理。
3. **`-` 作为伪文件名的惯例**：
   - 当参数需要文件路径时，单个 `-` 约定代表**从标准输入 (`stdin`) 读取**或**向标准输出 (`stdout`) 写入**。

## 四、 标准输出 (`stdout`) 与标准错误 (`stderr`) 的安全分流铁律

* **`stdout` 是机器消费的流**：
  - 只能输出下游管道、重定向文件或调用方需要处理的纯数据载荷（Payload）。
  - **严禁向 `stdout` 输出任何修饰性废话**（如 `Done in 2.3s`、`[INFO] Starting...`、进度条）。
* **`stderr` 是人类与运维的流**：
  - 所有的日志打点、诊断信息、警告、错误栈、进度条全部写入 `stderr`。
  - 无论是否重定向 `stdout`，运维人员在控制台依然能清晰看到故障原因。
